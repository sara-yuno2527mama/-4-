# みらいプロジェクト（`/mirai`）横断スケジュール・番組表 — 相談合意

**目的**: 事務局の「今日・今週・業務月」を横断的に見せ、番組表型の日次計画・実績・当番を一体で扱う  
**形式**: 相談合意（実装は開発チャットで行う）  
**日付**: 2026年6月  
**関連**: [mirai-storage-design.md](./mirai-storage-design.md)（永続化の置き場）

---

## 1. 背景と課題

現状の `/mirai` 4ペインは **領域ごとにスケジュール帯が Pane2 に閉じている** ため、事務局全体が「今どの時期か」「今日何をいつやるか」を一度に見えない。

### 合意した方向

| 論点 | 決定 |
|------|------|
| 横断の主軸 | **今日基準**（今週・今の締めで何をやるか） |
| 今週の定義 | **カレンダー週（月〜日）** |
| 横断帯の中身 | **すべて**（フェーズ名・期限近い件数・マイルストーン日付） |
| 日次 UI | **番組表**（縦=時間、横=業務列） |
| 業務月 | **請求締め日ベース**（暦月ではない） |

---

## 2. 4ペイン再設計（役割）

```
┌─ 横断帯（全幅）────────────────────────────────────────────┐
│ 今日 · 今週 · 業務月 · 業務時間バー · アラート              │
└────────────────────────────────────────────────────────────┘
┌─ ペアに振った仕事（別枠）──────────────────────────────────┐
│ 期限付き · 進捗確認 · 振った側が [完了] で消える            │
└────────────────────────────────────────────────────────────┘
┌─ 繰越（前日未完了）──────────────────────────────────────────┐
┌ Pane1 ─── 時期 · すぐ入力 · 当月メモ ────────────────────────┐
┌ Pane2 ─── 列ピッカー · 番組表（主/ペア） · 月次/年次サマリ ──┐
├ Pane3 ─── 読む（詳細 · 予実差 · 選択ブロック）───────────────┤
└ Pane4 ─── 書く（編集 · タイマー · ペアに振る）───────────────┘
```

| Pane | 役割 |
|------|------|
| **Pane1** | 日付・今週・月選択、**すぐ入力**、**当月メモ**、各月**請求締め日** |
| **Pane2** | 列ピッカー、**番組表**（主/ペアタブ）、タスク一覧、月次/年次業務量 |
| **Pane3** | 読む（Pane3=読む / Pane4=書く を維持） |
| **Pane4** | 予定編集、**スタート/ストップ**タイマー、ペアに振る |

既存の領域別タスク・実行委員会次第・A4 等は Pane2〜4 に残す。Pane1 の Sidebar 領域選択は **Pane2 領域タブ** へ移行する。

## 4. 業務月・請求締め日

### 4.1 業務月の定義

カレンダー月（1日〜末日）ではなく、**月初の請求書締めが終わるまで**を1業務月とする。

```
業務月 M の集計期間 =
  （M-1 の請求締め日の翌日） 〜 （M の請求締め日）  … 両端含む
```

### 4.2 締め日入力

- 各 **業務月ごとに請求締め日を1つ**（月によって異なる）
- **判明次第すぐ入力**（Pane1「すぐ入力」）
- 未入力の月 → 横断帯に **入力促し**

業務量の **月次・年次集計** は **実績時間（タイマー）** を列×業務月で合算する。

## 5. すぐ入力・当月メモ

### 5.1 2つの入力モード

| モード | 用途 |
|--------|------|
| **クイック入力** | 日付が分かった瞬間に1件追加（主） |
| **当月メモ** | 追加済みの一覧確認・修正 |

### 5.2 すぐ入力の項目

| 項目 | 入力 | 反映 |
|------|------|------|
| **締め日** | 業務月ごと1日 | 業務月期間・集計 |
| **昼当番** | 日付 + 追加 | 当月メモ + 当番ブロック自動 |
| **郵便当番** | 日付 + 追加 | 同上 |
| **郵便+定期便** | 該当日にチェック | 15:45–16:15 当番 + **16:15退勤** |
| **お弁当** | 日付 + 追加 | プライベート列 + **3日前アラート** |
| **休み** | 日付範囲 or 複数 + 種別 | 番組表グレー / 半休 |
| **実行委員会・事前打合せ** | 種別 + 日付（+ 時刻任意） | 当月メモ + 横断帯 + 該当日ブロック候補（§16.1） |

### 5.3 当月メモ（表示例）

```
締め 6/3 │ 昼当 5/7, 5/21 │ 郵便 5/3, 5/17+定期 │ お弁当 5/15
委員会 6/28 │ 事前打合せ 5/24 │ 発表会 11/23 │ 休み …
```

## 6. 当番・お弁当・休み（日次自動ブロック）

### 6.1 日タイプ一覧

| 日タイプ | 時間帯 | 列 |
|----------|--------|-----|
| **通常** | 12:00–13:00 昼休み（業務不可） | — |
| **昼当番** | 12:00–13:00 電話番（業務遂行可）／13:00–14:00 昼休み | 総務全体 |
| **郵便当番** | **9:05–9:35** 朝仕分け／13:00起 **約30分** 昼仕分け | 総務全体 |
| **郵便+定期便** | 上記 + **15:45–16:15** 定期便仕分け | 総務全体 |
| **お弁当** | プライベート列にマーク | プライベート |
| **AM休 / PM休** | 半休グリッド（§7） | — |
| **有休・休日** | 終日不可 | — |

当番ブロックは **locked**（システム固定）。予定ブロックと区別して表示する。

### 6.2 当番の修正・入れ替え

- 日付変更・削除・**担当者（主/ペア/他）の入れ替え**が可能
- 修正後、該当日の当番ブロックを **再生成**
- 主/ペア **2枚の番組表** では、担当者の枚にだけ当番を表示

### 6.3 お弁当アラート

- お弁当日の **3日前** から「買い出し」アラート（横断帯 or Alert）
- 任意で「買い出し済み」チェック

### 6.4 当番と半休・休みの重なり

重複日は **警告**（都度判断）。例: AM休 + 昼当番、有休 + 郵便。

## 7. 勤務時間・15:30 ルール・定期便例外

### 7.1 通常日

| 概念 | 時刻 |
|------|------|
| 勤務枠 | **9:00 – 16:00**（時短） |
| **番組表に載せる業務の終了** | **〜15:30** |
| **15:30 – 16:00** | 退勤準備バッファ（**予定不可**） |
| 退勤 | **16:00** |

「16時まで業務を詰めると帰れない」ため、**計画は15:30まで**。

### 7.2 郵便+定期便日（残業確定）

| 概念 | 時刻 |
|------|------|
| 通常予定 | 〜15:30 |
| 当番 | **15:45 – 16:15** 定期便（固定・例外） |
| 退勤 | **16:15 頃** |

横断帯に **「本日は定期便のため16:15退勤（残業）」** と明示する。

### 7.3 業務時間バー

- その日の **実質可能時間** を日タイプで計算
- **15:30時点**（定期便日は15:30以前の予定のみ）で「終わらない見込み」アラート

## 8. 番組表（日次）

### 8.1 主体

- **主・ペア 2枚**（タブ切替）（合意 B=b）
- 共通: 締め日、業務月、列ピッカー、横断帯、当月メモ

### 8.2 予定と実績

```ts
dailyBlock {
  columnId,
  plannedStart, plannedEnd,
  actualStart?, actualEnd?,   // タイマー or 手入力
  done?: boolean,             // 完了（§18 繰越判定の土台）
  assignee?,                  // 主 / ペア（実績の帰属）
  title, taskId?, note?
}
```

- **タイマー**: **スタート / ストップ**（端末で同時1本のみ。走行中は `{blockKey, startedAt}` を永続しリロードでも継続）
- ストップで実績記録 → **予定との差**を Pane3 で表示（停止時に「完了にする?」を促す）
- 未計画の割り込みは列だけ選んでタイマー開始 → 停止で **実績ブロックを新規生成**（`other` 等）
- 日次サマリ: 予定合計 / 実績合計 / 差分（主/ペア別に集計）
- 止め忘れ・手修正・帰属の詳細は **§18**

### 8.3 半休

その日の番組表上部: `[通常] [AM休] [PM休]`

| モード | 編集可能時間（案） |
|--------|-------------------|
| 通常 | 9:00–12:00, 13:00–15:30（+当番で変動） |
| AM休 | **13:00–15:30** 中心。上段灰色 |
| PM休 | **9:00–12:00** 中心。下段灰色 |

### 8.4 繰越（§18 で詳細確定）

- 予定日を過ぎた **未完了** ブロックは、**完了 / 破棄まで繰越トレイに出続ける（累積）**
- 判定は **都度計算（派生）**：`asOfDate` 基準で「予定日 < 今日 かつ 未完了」を集める（バッチ・実体化なし）
- **[今日に載せる]** は **移動**（複製でなく予定日を today に上書き。seed 由来はオーバーレイ）
- ペア別枠の期限超過は別枠に残す or 繰越（Phase 4・実装時に選択）

## 9. ペアに振った仕事（別枠）

メイン番組表とは **別枠** で表示し、忘れ防止する。

| 項目 | 内容 |
|------|------|
| アクション | **ペアの担当者に振る**（内容・期限・**振った日**・列・メモ） |
| 表示 | 期限付きリスト（横断帯の下・メインと同時に見える位置。**0件でも細い帯を表示**） |
| 進捗 | **当面なし**（1人運用。将来ペア展開時に未着手/対応中等を検討） |
| 完了 | **振った側（私）が [完了]** → 別枠から **消える** |

### 9.1 UX 詳細（2026-07 相談合意）

**入力項目**

| 項目 | 必須 | 備考 |
|------|------|------|
| 内容 | ✅ | |
| 期限 | ✅ | |
| **振った日** | ✅ | 日付ピッカーで選べる（後から修正可。既定=今日） |
| 業務列 | 任意 | |
| メモ | 任意 | |
| 振った側 | 自動 | `createdBy`（端末ロール） |

**操作・表示**

- 入口：**別枠の [+ 振る]** と **番組表 DetailRail**（Pane4 相当）
- **0件でも** 別枠は細い帯を常時表示（「なし + ペアに振る」）
- リストは **全件共有**（将来ペアも同じリスト）
- **[完了]** / **[取消]** は振った側（`createdBy`）のみ

**端末**

- 会社PC・自宅PCの両方から触る → 本番は **DB 同期**（storage §10）。localStorage は開発用。

**Wave 1 → Wave 1.5**: 初版実装に `delegatedOn`（振った日）・空別枠常時表示・進捗 UI 省略を反映する。

## 10. 横断帯

基準日 `asOfDate`（デフォルト=今日）で全領域を1行〜カード表示:

- 現在フェーズ名（総務締め / 参観フェーズ / 委員会月 等）
- 期限が近い件数
- マイルストーン日付
- 業務時間バー・15:30/16:00/16:15 アラート
- お弁当3日前、ペア振り期限、AI ナudge（Phase B）
- 実行委員会・事前打合せの **確定日程**（§16.1）
- 参観列の **コンテスト集約タイミング** 備忘（§16.3）
- 発表会 **11/23** カウントダウン・外部表タスク（§16.2）

## 11. AI・ルールアラート

### Phase A（ルール・先に実装）

- 15:30 までに予定が終わらない見込み
- 9:00前 / 15:30後（16:15除く）の予定配置
- 今週期限タスクが番組表にない
- 締め関連タスク未配置
- お弁当3日前
- ペア振り期限
- 実行委員会・事前打合せの **1か月前後** 未入力（日程決定の目安）
- 作文・写真コンテスト **集約期日** 接近
- 発表会入賞者 **出欠未確認**

### Phase B（AI・自然文）

Phase A の信号 + 当日データを渡し、提案のみ（**自動で予定を書き換えない**）。

例:

- 「このペースだと15:30前に終わりません。委員会を短くするか、出張を明日に回せます」
- 「ETC（新電電）の締めタスクが未配置です」

## 12. シフト表写真取込（Phase 2）

1. **Phase 1**: 手入力・クイック追加（本ドキュメントのすぐ入力）
2. **Phase 2**: 写真アップロード → AI が日付候補抽出 → **確認プレビュー** → 反映
3. 昼当番・郵便・定期便を種別分類。**必ず人が確認してから保存**

## 18. Phase 3 後半 詳細仕様（タイマー / 実績 / 繰越）— 相談合意 2026-07

### 18.0 前提（「主とペアは別端末」確定の帰結）

- 運用データ（予定編集・実績・完了・繰越・当月設定）は **repository 抽象（async）越し**に読み書きする。**localStorage は開発・デモ専用**、本番は **DB**（[storage 設計 §10](./mirai-storage-design.md)）。
- 識別は端末ローカルの **「主/ペア」軽量ロール**（認証は次フェーズ）。編集は既定で **自分の枚**、相手は閲覧（軽量識別のため当面ソフト、強制は本格認証で）。
- **プロトタイプ期（localStorage）は端末独立・同期なし。** 真の主/ペア協働は DB 投入後に成立。ここで検証するのは「1 人分の操作感」まで。

### 18.1 タイマー / 実績

| 項目 | 合意 |
|------|------|
| 同時本数 | **端末で 1 本**（`runningTimer`）。走行中は `{blockKey, startedAt, assignee}` を永続 → リロード/再訪で継続 |
| 開始 | 予定ブロックから開始、または **未計画は列だけ選んで開始** |
| 停止 | `actualEnd`=停止時刻、`actualStart`=開始時刻。停止時に **「完了にする?」** を促す（§18.2） |
| 未計画実績 | 停止で **実績ブロックを新規生成**（`other` 等） |
| 止め忘れ | 走行中は **横断帯＋番組表に赤表示**。停止時に終了時刻を手で丸め可 |
| 手修正 | 実績 `開始/終了 HH:mm` を後から編集可（設計「タイマー or 手入力」） |
| 予実差 | Pane3 選択ブロックで **予定/実績/差**、日次サマリで **予定合計/実績合計/差分**（`dayWorkloadSummary` の実績版を追加）。`assignee` で主/ペア別に集計 |

### 18.2 完了

- 完了は **明示✓を主**とする。タイマー停止時に「完了にする?」を促す（**実績があっても未完了は残せる**）。
- 保持先: 運用ブロックは `dailyBlock.done`、seed 由来は `blockOverride.done`。

### 18.3 繰越

- **都度計算（派生）**：`asOfDate` 基準で「予定日 < 今日 かつ 未完了」を集めるだけ（バッチ・実体化なし。CLAUDE.md「派生はレンダーで計算」準拠）。
- **累積**：予定日を過ぎた未完了は **完了 / 破棄まで** 繰越トレイに出続ける。
- **[今日に載せる] = 移動**：予定日を today に上書き（複製でなく＝二重計上防止）。seed 由来は `blockOverride.dateOverride`。
- **[破棄]** で繰越から外す（完了扱いにせず消す用途）。
- ペア別枠（Phase 4）の期限超過の扱いは別途。

### 18.4 データモデル差分（§13 追補）

- `dailyBlock` に `done?` / `assignee?`（`actualStart/End` は既存）
- `runningTimer`（端末 1 本）
- `blockOverride`（seed 由来ブロックの `dateOverride` / `done` / `actual`）

### 18.5 実装の申し送り（開発チャット）

1. 着手前に **repository 抽象（async）** を導入。現 `hooks/use-mirai-roster.ts`（`useSyncExternalStore` + localStorage 直読み）→ **localStorage アダプタ**に作り替え。
2. Phase 3 後半の UI/ロジックは **抽象越し**に書く。
3. **DB アダプタ ＋ 最低限の書込ゲート**は事務局展開前に（storage 設計 §10）。
